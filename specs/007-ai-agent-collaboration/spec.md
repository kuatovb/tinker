# Спецификация tinker: совместная работа ИИ

**Ветка:** main. **Статус:** разработка автоматической связки отложена; требования и задачи сохранены.

**Назначение:** координатор готовит и передаёт согласованные задания исполнителю, получает вопросы и результаты, проводит независимую проверку. Первая версия проектируется для Codex и Antigravity; расширение на другие ИИ требует отдельных адаптеров.

**Границы:** механизм относится только к оркестрации tinker. Самостоятельная работа пользователя в любом ИИ не требует tinker или доступности другого ИИ. Персональные настройки, разрешения и авторизация исполнителей сохраняются.

## Пользовательские сценарии и проверка

### История 1 — передача согласованной задачи исполнителю (приоритет P1)

Пользователь согласовывает объём работы в Codex. Codex передаёт Antigravity задачу с требованиями, разрешёнными файлами и критериями приёмки. Antigravity реализует её и возвращает результат в ту же работу Codex.

**Почему этот приоритет:** это основной сценарий разделения ролей, ради которого создаётся связка.

**Независимая проверка:** передать небольшую согласованную задачу, получить изменение разрешённого файла и отчёт исполнителя в Codex без переноса текста пользователем.

**Сценарии приёмки:**

1. **Дано** согласованное задание с планом и списком разрешённых файлов, **когда** Codex передаёт его исполнителю, **тогда** Antigravity получает полное задание, границы доступа и идентификатор работы.
2. **Дано** задание в реализации, **когда** Antigravity возвращает результат, **тогда** Codex получает ответ, список заявленных изменений и результаты заявленных проверок; работа переходит в состояние проверки.
3. **Дано** задание связки, не согласованное пользователем, **когда** Codex предлагает начать реализацию, **тогда** исходники не изменяются до согласования. Это не запрещает пользователю отдельно поручать работу Antigravity по его собственному workflow.

### История 2 — вопросы и уточнения между агентами (приоритет P1)

Antigravity обнаруживает недостаток технического контекста или ограничение доступа и передаёт вопрос Codex. Codex отвечает в рамках согласованного объёма либо передаёт пользователю решение, меняющее требования. Исполнитель продолжает именно свою работу с сохранённым контекстом.

**Почему этот приоритет:** одноразовая передача задания без обратной связи не соответствует требованию общения агентов.

**Независимая проверка:** исполнитель задаёт технический вопрос; Codex возвращает ответ; исполнитель продолжает ту же работу и учитывает ответ.

**Сценарии приёмки:**

1. **Дано** уточнение исполнителя по существующему плану, **когда** оно поступает в Codex, **тогда** вопрос виден вместе с идентификатором задачи и контекстом, без автоматического утверждения новой функциональности.
2. **Дано** две независимые работы, **когда** Codex отвечает первой, **тогда** ответ попадает только в её сессию; вторая работа не получает его.
3. **Дано** вопрос, требующий изменения требований или расширения доступа, **когда** Codex оценивает его, **тогда** зависимая работа приостанавливается до решения пользователя, а согласованные независимые действия могут продолжаться.

### История 3 — проверка и возврат замечаний (приоритет P1)

Codex независимо проверяет изменения Antigravity. При наличии замечаний Codex возвращает их исполнителю в рамках исходного задания. Исполнитель исправляет результат, а Codex повторяет относящиеся к изменениям проверки.

**Почему этот приоритет:** отметка исполнителя о завершении не должна заменять доказательства соответствия требованиям.

**Независимая проверка:** исполнитель возвращает результат с воспроизводимым дефектом; Codex обнаруживает дефект, передаёт замечание, получает исправление и подтверждает результат повторной проверкой.

**Сценарии приёмки:**

1. **Дано** успешное сообщение исполнителя, **когда** независимая проверка обнаруживает нарушение плана, **тогда** работа остаётся незавершённой и замечание возвращается исполнителю.
2. **Дано** исправленный результат, **когда** проверки подтверждают критерии приёмки, **тогда** Codex отмечает работу завершённой, а задачи содержат ссылки на фактические доказательства.
3. **Дано** недоступная проверка, **когда** формируется отчёт, **тогда** отчёт указывает, что именно не проверено и почему; недоступная проверка не считается успешной.

### История 4 — наблюдение и остановка работы (приоритет P2)

Пользователь видит текущее состояние и может остановить выполнение. После завершения текущей операции агенты не начинают новое изменение по остановленной работе. Сохранённых данных достаточно, чтобы продолжить согласованную задачу позднее.

**Почему этот приоритет:** длительная работа должна оставаться управляемой и понятной пользователю.

**Независимая проверка:** начать работу, получить статус, остановить её и затем продолжить по её идентификатору, сохранив изменения и предыдущий результат.

**Сценарии приёмки:**

1. **Дано** длительное выполнение, **когда** пользователь запрашивает состояние, **тогда** доступны агент, задача, текущий этап и последнее содержательное событие.
2. **Дано** остановленное выполнение, **когда** пользователь продолжает его, **тогда** сохраняются план, результаты и сведения о незавершённых действиях; работа другого задания не возобновляется.

### История 5 — работа на другом компьютере (приоритет P1)

Пользователь получает репозиторий на другом устройстве или перемещает его в каталог с другим именем. Связка использует корень этой рабочей копии и установленные на устройстве инструменты, без обращения к каталогам предыдущего компьютера.

**Почему этот приоритет:** пользователь продолжает разработку с разных устройств; персональные пути не должны становиться частью проектного контракта.

**Независимая проверка:** выполнить настройку и одну небольшую задачу из двух разных каталогов, один с пробелами и кириллицей, с разными путями инструментов; дополнительно проверить запуск на другом Windows-устройстве.

**Сценарии приёмки:**

1. **Дано** checkout в новом каталоге, **когда** выполняется локальная настройка, **тогда** корень и зависимости определяются для этой копии; в коммитируемых артефактах отсутствуют пути и имя пользователя прежнего устройства.
2. **Дано** нестандартная установка CLI, Python, JDK или SDK, **когда** пользователь задаёт локальный путь, **тогда** путь проверяется и используется только на этом устройстве; переноса настройки другому пользователю не требуется.
3. **Дано** отсутствующий инструмент или чужой локальный идентификатор сессии, **когда** начинается работа на новом устройстве, **тогда** выводится конкретная причина и способ восстановления контекста; подстановка несуществующего старого пути или чужой сессии запрещена.

### История 6 — самостоятельный Antigravity при недоступном Codex (приоритет P1)

Лимиты Codex исчерпаны либо Codex временно отсутствует. Пользователь открывает проект в Antigravity и продолжает работу по его собственным правилам, используя сохранённые требования и результаты. После восстановления лимитов Codex сверяет фактические изменения и продолжает с актуального состояния.

**Почему этот приоритет:** интеграция должна помогать работе в Codex, сохраняя возможность разработки в Antigravity независимо от него.

**Независимая проверка:** сохранить контекст и остановить оркестрацию Codex, выполнить небольшую задачу в самостоятельном Antigravity при недоступном Codex, затем возобновить Codex и сверить изменения без повторного выполнения готовой задачи.

**Сценарии приёмки:**

1. **Дано** самостоятельный запуск Antigravity, **когда** Codex или мост отсутствуют, **тогда** работа не требует ответа, проверки, авторизации или лимитов Codex; исходные правила Antigravity действуют без дополнений связки.
2. **Дано** исчерпание лимитов Codex во время совместной работы, **когда** управление передаётся пользователю, **тогда** доступен последний сохранённый контекст: требования, изменения, проверки и незавершённые действия. Сохранение уже имеющегося контекста не требует нового ответа модели Codex.
3. **Дано** активный пишущий процесс, **когда** запрошена передача управления, **тогда** новый пишущий процесс не запускается одновременно с прежним; блокировка оркестрации не превращается в постоянный запрет самостоятельной работы после безопасной передачи.
4. **Дано** работа, продолженная в Antigravity, **когда** Codex возвращается, **тогда** он сверяет фактические файлы, Git и отмеченные задачи, сохраняет изменения пользователя и не повторяет уже выполненные действия по старому состоянию.

### История 7 — лимиты Antigravity и точка остановки (приоритет P1)

Codex проверяет остаток доступных лимитов исполнителя перед заданием, между ходами и во время длительного исполнения. При малом остатке либо исчерпании он сообщает пользователю, сохраняет, на какой задаче остановился Antigravity, и не выдаёт частичный результат за завершённую работу.

**Независимая проверка:** малый остаток и исчерпание приводят к уведомлению с task/work ID, последним подтверждённым действием, изменёнными файлами, проверками и незавершённой границей; новый ход не запускается до восстановления доступности и сверки.

**Сценарии приёмки:**

1. **Дано** доступные актуальные лимиты выбранной модели, **когда** остаток одного применимого окна достигает порога, **тогда** Codex сообщает пользователю и сохраняет checkpoint; следующая генерация по этой работе не начинается.
2. **Дано** исчерпание во время реализации, **когда** исполнитель возвращает сообщение о квоте, **тогда** Codex сверяет реальные файлы и последний подтверждённый результат, отделяет непроверенные действия, записывает точку остановки без дополнительного ответа модели Antigravity и уведомляет пользователя.
3. **Дано** неработающий источник, устаревшая квота либо неизвестная группа модели, **когда** Codex проверяет лимит, **тогда** неизвестное значение не считается нулём или полным остатком; недоступность видна пользователю, новые ходы заблокированы до достоверной проверки.
4. **Дано** восстановление квоты, **когда** работа продолжается, **тогда** сначала проверяются свежие лимиты, фактическое состояние и согласованный scope; уже выполненные задачи не запускаются повторно.

### Граничные случаи

- Исполнитель возвращает пустой ответ при формально успешном статусе: работа не считается выполненной, фиксируется отсутствие результата.
- Исполнитель не получил доступ к инструменту: отказ виден Codex вместе с необходимым действием; глобальное отключение проверок доступа не выполняется автоматически.
- Процесс завершился успешно, но результат содержит ошибку сервиса: работа отмечается ошибкой, текст ответа не подменяет статус.
- Ответ повреждён, отсутствуют обязательные сведения или процесс завершился с ошибкой: фиксируется явная ошибка обмена, задачи не отмечаются выполненными.
- Истёк срок ожидания: фиксируется таймаут и неизвестный результат незавершённого действия; повтор не запускает автоматически ещё одного пишущего исполнителя.
- Сессия не найдена: система не продолжает глобальную последнюю сессию и сообщает о потере контекста.
- Другая работа уже меняет тот же checkout: новое пишущее выполнение блокируется до освобождения checkout либо выбора изолированной копии.
- Между этапами изменились файлы пользователя: изменения сохраняются, конфликт сообщается, автоматическое перезаписывание запрещено.
- Обнаружены изменения вне разрешённого объёма: независимая проверка отклоняет результат и сообщает пользователю о расхождении.
- В локальном пути есть пробелы или кириллица: передаваемые значения сохраняются без повреждения и трактуются как пути, а не дополнительные команды.
- Репозиторий перенесён, а сессии агента остались на старом устройстве: переносимый контекст доступен, но локальная сессия не считается перенесённой автоматически.
- Лимиты Codex исчерпаны: состояние требует передачи управления, не выдаётся за завершённую работу и не блокирует самостоятельный Antigravity.
- Codex возвращается после самостоятельных изменений: старые отметки состояния не имеют приоритета над фактическим Git и кодом.
- Счётчик использованных токенов сессии не является остатком квоты аккаунта; квота другой группы моделей не подменяет нужную.
- Во время исчерпания исполнитель не может ответить ещё раз: точка остановки строится из сохранённых событий и фактических файлов, без запроса «где остановился» к модели.
- Предупреждение о квоте не доказывает прекращение активной записи; безопасная передача сохраняет требования единственного writer и проверки незавершённых операций.

## Требования

### Функциональные требования

- **FR-001**: В режиме совместной работы, инициированном Codex, связка MUST назначать Codex ответственность за подготовку требований, планов и задач, контроль выполнения и независимую проверку; Antigravity — за код, скрипты, тесты, техническую документацию и отчёт о выполнении. Codex может запускать готовые проверки для независимого ревью, но не подменяет исполнителя написанием его артефактов. Это распределение не распространяется на самостоятельную работу пользователя в Antigravity.
- **FR-002**: Каждое задание MUST содержать уникальный идентификатор, цель, ссылки на согласованные артефакты, границы файлов, разрешённые действия и критерии приёмки.
- **FR-003**: Связка MUST передавать задания, вопросы, ответы и результаты между агентами без ручного копирования пользователем и сохранять принадлежность каждого сообщения конкретной работе.
- **FR-004**: Продолжение MUST использовать идентификатор конкретной сессии исполнителя; выбор глобальной последней сессии запрещён.
- **FR-005**: Связка MUST различать состояния «ожидает согласования», «в реализации», «требуется ответ», «на проверке», «завершено», «ошибка», «остановлено» и «передано пользователю». Последнее состояние не ограничивает самостоятельную работу Antigravity.
- **FR-006**: Исполнитель MUST возвращать список заявленных изменений, фактически запущенные проверки, их результаты и ограничения. Неисполненная проверка не может маркироваться как успешная.
- **FR-007**: Отметка Antigravity о выполненной задаче MUST считаться заявлением исполнителя до независимой проверки Codex. Codex MUST проверять фактический diff и критерии приёмки перед завершением работы.
- **FR-008**: Codex MUST иметь возможность вернуть замечания в ту же работу Antigravity и получить повторный результат.
- **FR-009**: Запуск MUST иметь ограниченный срок ожидания, заданный для работы; ошибки сервиса, процесса, формата ответа, пустые результаты и отказы доступа MUST оставаться явными ошибками.
- **FR-010**: Связка MUST запрещать одновременную запись двух исполнителей в один checkout. Независимые чтение и проверки допустимы; параллельная реализация требует отдельных изолированных копий и согласованного объёма.
- **FR-011**: Действия MUST соблюдать правила проекта и действующие разрешения среды. Запросы на расширение требований, необратимые действия или доступ сверх согласованного объёма MUST передаваться пользователю.
- **FR-012**: Связка MUST сохранять состояние и события работы локально для наблюдения и продолжения; локальные ответы, журналы и настройки не должны автоматически попадать в Git.
- **FR-013**: Связка MUST не собирать и не передавать секреты из локальных конфигураций, ключей подписи и файлов авторизации. Авторизация агентов использует их существующие локальные настройки; секреты не включаются в планы и отчёты.
- **FR-014**: Пользователь MUST иметь возможность запросить статус, остановить работу и продолжить её по идентификатору. Остановка не должна уничтожать готовые изменения.
- **FR-015**: AI-инструменты MUST оставаться отдельным инструментарием разработки, без зависимости runtime пользовательских проектов от их наличия, сети или авторизации.
- **FR-016**: Коммитируемые настройки связки MUST не содержать привязок к диску, имени пользователя или каталогу конкретного устройства. Корень проекта и инструменты MUST определяться относительно текущей копии и текущей среды, с возможностью явного локального переопределения и проверкой наличия.
- **FR-017**: Настройка на новом устройстве MUST сохранять посторонние локальные настройки и быть повторяемой без дублирования записей. Пути с пробелами и кириллицей MUST поддерживаться.
- **FR-018**: Переносимые ссылки на проектные артефакты MUST относиться к корню репозитория. Локальные пути, авторизация и идентификаторы сессий MUST оставаться данными текущего устройства; их доступность проверяется перед продолжением. Контекст передачи MUST не содержать секретов.
- **FR-019**: Правила оркестрации MUST быть подключены только к Codex. Связка MUST не изменять правила, skills, workflow или обязательные разрешения Antigravity и не добавлять ему постоянное требование ждать Codex. Ограничения конкретного задания передаются в этом задании.
- **FR-020**: Пользователь MUST иметь возможность продолжить в самостоятельном Antigravity без запущенного или доступного Codex и без установленного моста. Готовые артефакты MUST быть читаемы обычным workflow Antigravity.
- **FR-021**: Связка MUST сохранять контекст передачи до исчерпания лимитов либо из уже имеющихся данных без нового обращения к модели Codex. Она MUST обозначать границу незавершённой операции и безопасно передавать исключительное право записи, не уничтожая изменения.
- **FR-022**: При возвращении Codex связка MUST сверять код, Git, задачи и результаты самостоятельной работы Antigravity перед продолжением; устаревшее состояние не может перезаписать изменения или повторно запустить выполненную задачу.
- **FR-023**: Codex MUST проверять доступный остаток применимых квот Antigravity для выбранной модели перед каждым генерирующим ходом и регулярно во время длительного исполнения. Данные MUST содержать источник, время проверки, окно/группу и срок восстановления, если он предоставлен; недоступность/устаревание не подменяются фиктивными значениями или session token usage.
- **FR-024**: При достижении настраиваемого порога малого остатка либо подтверждённом исчерпании связка MUST блокировать следующий генерирующий ход, сохранить текущую границу исполнения и дать Codex уведомление пользователю. Она MUST не запускать автоматические повторы, менять модель/аккаунт или подключать платный резерв для обхода квоты. Ограничение относится только к оркестрации Codex, не меняет самостоятельные правила Antigravity.
- **FR-025**: Codex MUST записать проверяемую точку остановки: work/task ID, последнее подтверждённое действие, фактические изменённые пути, результаты проверок, непроверенные/незавершённые операции и следующий шаг. Эта запись MUST создаваться из уже имеющихся данных без новой генерации Antigravity; факт остановки writer и полный успех не утверждаются при неизвестном исполнении. Продолжение требует свежей квоты и сверки состояния.

### Основные сущности

- **Работа**: согласованный объём, идентификатор, состояние, исполнитель, рабочая копия, срок ожидания и критерии приёмки.
- **Сообщение**: отправитель, получатель, принадлежность работе, тип (задание, вопрос, ответ, результат, замечание) и содержание.
- **Результат исполнителя**: заявленные изменения, фактические проверки, ошибки и ограничения, контекст продолжения.
- **Проверка Codex**: подтверждённый diff, критерии приёмки, результаты независимых проверок и замечания.
- **Согласование**: пользовательское решение об объёме или расширении доступа, связанное с конкретной работой.
- **Локальная среда**: текущая рабочая копия, пути установленных инструментов и доступные локальные сессии; не переносится как универсальная настройка другого устройства.
- **Контекст передачи**: переносимые ссылки на требования и задачи, последний результат, доказательства проверок и незавершённые действия для самостоятельного продолжения.
- **Проверка квоты**: выбранная модель/группа, применимые окна, доступный остаток, время/источник проверки, доступность и срок восстановления; отдельна от token usage сессии.

## Критерии успеха

### Измеримые результаты

- **SC-001**: Одна небольшая согласованная задача проходит передачу, реализацию и независимую проверку без ручного копирования сообщений пользователем.
- **SC-002**: Один технический вопрос исполнителя получает ответ Codex в той же работе; результат учитывает ответ.
- **SC-003**: Один обнаруженный Codex дефект проходит возврат замечания, исправление Antigravity и успешную повторную проверку.
- **SC-004**: Во всех проверенных сценариях ошибок обмена, отказа доступа, пустого результата и таймаута работа не отмечается завершённой и сохраняет понятную причину.
- **SC-005**: В проверке двух независимых работ отсутствуют чужие сообщения и одновременные изменения одной рабочей копии.
- **SC-006**: После остановки и продолжения сохраняются идентификатор работы, предшествующие сообщения и готовые изменения; новая запись без продолжения не начинается.
- **SC-007**: Одна задача успешно запускается из двух разных путей, включая пробелы и кириллицу, и на втором Windows-устройстве после его локальной настройки; старые персональные пути не используются. Проверка второго устройства не подменяется проверкой второго каталога.
- **SC-008**: При недоступном Codex пользователь завершает небольшую задачу непосредственно в Antigravity; возврат Codex сохраняет изменения и не повторяет завершённые действия.
- **SC-009**: До и после настройки содержимое исходных правил/skills Antigravity совпадает; самостоятельный запуск не требует моста или обращения к Codex.
- **SC-010**: В сценарии исчерпания лимитов контекст доступен без нового ответа модели Codex и одновременно существует не более одного пишущего процесса по переданной работе.
- **SC-011**: В проверке малого остатка и исчерпания применимой квоты новый ход не запускается; пользователь получает уведомление с точкой остановки и доступным временем восстановления, без ложной отметки complete.
- **SC-012**: В проверках недоступного источника, просроченной квоты и чужой группы ни одно неизвестное значение не выдаётся за доступный остаток; причина и запрет новой генерации видны пользователю.
- **SC-013**: После исчерпания точка остановки сохраняется без нового модельного запроса исполнителю; при восстановлении продолжается только фактически оставшийся объём после сверки, без двух writers.

## Допущения и границы

- Первая версия предназначена для локальной разработки на Windows, включая разные устройства, пользователей и каталоги этого репозитория. Поддержка macOS/Linux в первой версии не заявляется. Для режима связки нужны оба установленных и авторизованных CLI; самостоятельному Antigravity Codex не требуется.
- Пользователь инициирует работу в Codex и согласовывает требования. Codex разрешает обычные технические уточнения в согласованном объёме; новые бизнес-решения остаются за пользователем.
- Исходный порог малого остатка — 20% любого применимого окна; он настраивается локально. Проверка перед каждым ходом обязательна, начальный интервал наблюдения во время длительной работы — 60 секунд. Эти значения — явные настраиваемые допущения; квота провайдера не гарантирует стоимость или успешное окончание одного хода.
- Сеть и доступность провайдеров агентов нужны для генерации ответов; временная недоступность не подменяется фиктивным результатом.
- Совместная работа использует существующие Spec Kit артефакты и правила проекта. Их изменение или замена не входят в эту функцию.
- Самостоятельный Antigravity следует своему исходному workflow; проверки Codex и правила связки применяются только после возвращения в Codex, без блокирования самостоятельной работы.
- Передача между устройствами переносит согласованные артефакты и код через обычный Git workflow; личные настройки, секреты и журнал всех сессий автоматически в Git не публикуются.
- Автоматический merge, force-push, публикация, обход sandbox и глобальное отключение запросов разрешения не входят в функцию. Коммиты и push выполняются в соответствии с отдельной авторизацией и правилами проекта.
- Масштабный планировщик, облачная оркестрация, поддержка иных AI-провайдеров и изменение бизнес-логики пользовательских проектов не входят в первую версию.
