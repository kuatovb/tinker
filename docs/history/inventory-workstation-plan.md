# Очистка Android и взаимодействие AI-агентов — план реализации

> Для исполнителя: Antigravity выполняет согласованные задачи, Codex независимо проверяет diff и результаты. Использовать поэтапный workflow проекта. Пользователь подтвердил начало работ 2026-10-03; задача 2 сохраняет перечисленные ниже границы согласования спецификации и плана.

**Цель:** убрать подтверждённый лишний Android-шаблон, восстановить переносимую сборку и организовать передачу заданий и результатов между Codex и Antigravity.

**Архитектура:** сохранить текущие компоненты приложения и версии зависимостей. Для AI-инструментов использовать отдельный локальный CLI-мост и общие Spec Kit артефакты; приложение не зависит от AI-инструментов.

**Стек:** Windows PowerShell, Python, MCP, Codex CLI 0.160.0, Antigravity CLI 1.2.16, Gradle 9.7.1 / JDK 17 по последнему уточнению пользователя; исходная проверка и очистка выполнены на Gradle 8.7.

**Требование:** сообщения пользователя в текущем чате от 2026-10-03: новый компьютер, лишние Android-папки, Codex готовит планы/задачи, Antigravity реализует код, агенты обмениваются вопросами и результатами.

## Ограничения

- Не менять Kotlin-исходники, applicationId, flavors, API, миграции и архитектуру приложения.
- Не редактировать правила Antigravity, Spec Kit templates, скрипты и manifest-файлы ради адаптации Codex.
- Действующий Android root: `android/settings.gradle.kts`; основной модуль `android/app/build.gradle.kts`.
- Не включать `.env`, локальные настройки, AI-логи, кэши, ключи подписи и APK в Git.
- Проверять результат каждого CLI по статусу и коду завершения; ошибки не скрывать.
- Обновление AGP и исправление npm audit — отдельный объём, в этот план не включены.

## Проверяемые риски

- Удалить только вложенный шаблон, сохранив `android/app/src/` и настоящий build-файл.
- Wrapper должен скачивать именно Gradle 8.7 и работать из другого пути checkout.
- Timeout/HTTP 503/невалидный JSON/exit 0 со status ERROR должны завершать AI-задание ошибкой.
- Два агента не должны одновременно менять одни и те же исходники.
- Продолжать конкретную Antigravity-сессию по ID; не использовать глобальную «последнюю сессию» при параллельной работе.

## Задача 2: спецификация взаимодействия Codex и Antigravity

Это новая возможность инструментария, поэтому перед реализацией пройти проектные `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks` с предусмотренными границами согласования.

**Предлагаемые файлы:** `specs/<feature>/spec.md`, `plan.md`, `tasks.md`; после согласования — `scripts/ai/antigravity_bridge.py`, тесты моста и `docs/AI_COLLABORATION.md`. Точное имя feature назначить штатным Spec Kit workflow.

**Предлагаемый интерфейс для согласования:**

- `ask_antigravity(prompt, conversation_id=None)` передаёт задачу через `agy -p`, возвращает статус, ответ и conversation ID. Codex сохраняет ID и передаёт уточнение той же сессии.
- `run_codex_review(prompt)` вызывает `codex exec --sandbox read-only` для независимой проверки. Отзывы не запускают автоматическое изменение кода.
- Структурированные состояния задания: ожидание согласования → реализация → требуется ответ / проверка → готово / ошибка.
- Codex создаёт и уточняет plan/tasks; Antigravity изменяет исходники и отмечает задачи, прикладывая команды проверки; Codex самостоятельно проверяет результат.
- Один пишущий агент на checkout. Параллельная реализация требует изолированных worktrees и отдельных согласованных задач.
